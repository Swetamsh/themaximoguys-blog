equipment.

Additional fields for predecessor information
In the Graphical Scheduling or Graphical Scheduling - Large Projects application, create a
project and create a work query to specify the work orders. Create an optimization scenario. Three
new fields are available when you edit a constraint. The same fields are available in the Work Order
Tracking application, when you edit or display a relationship constraint.
Maximum Lead Lag Hours: It sets the maximum allowed delay between a
predecessor task and its successor. For example, if Task A happens before Task B, this value defines
how many hours at the most Task B can start after the start or end of Task A.Note: The default value
of 0 is not considered.
Optional Relationship: It indicates whether the dependency between a task
and its predecessor must always be followed. If set to yes, the dependency is mandatory and the
system treats it as a hard rule. If set to no, the dependency is optional and the system treats it
as a soft rule that is ignored, if the relaxOptionalRelationship model
parameter is set to true.
Use Lead Lag As Shift Hours: It specifies how the lead-lag duration is
interpreted. When set to no, the lead-lag is counted in calendar hours, that is, continuous time.
When set to yes, the lead-lag is counted in shift hours, that is, working hours. For example, if a
shift ends at 6 PM, Task A ends at 5 PM, and lead-lag is set to 2 hours, then if set to no, that is,
calendar hours, Task B can start at 7 PM on the same day. If set to yes, that is, working hours,
Task B would start on the next working day at 9 AM, after two working hours have passed from the 5
PM end time of Task A.

Explain why a work order is not assigned in Optimizer
In previous versions of Optimizer when work orders could not be
scheduled, the reason could be given as This work can not be assigned by the optimizer with all
selected optimization constraints. which was not a helpful message and did not tell you why the
work could be scheduled. Starting in 
Maximo Manage 9.2, a better
error messaging is provided to indicate exactly why the work could not be scheduled. It is
implemented for the Graphical Assignment and Graphical Scheduling models. 
In Graphical Assignment, a new AnalyzeUnperformed parameter is introduced.
When AnalyzeUnperformed is set to true there is a post process where every
single work order that was not scheduled is analyzed and a helpful alert is displayed stating which
business constraints could not be satisfied or which other work orders were in conflict that could
not prevent the work from being scheduled.
In Graphical Scheduling, there is a new iterativeConflictFixVerbose
parameter which when set to False prints all the constraints violated by the work orders that could
not be scheduled. 
These two parameters work across both models to give better and more comprehensive explanations
as to why certain work orders could not be scheduled allowing you to understand and fix the issues
in the schedule and ensure that maximum work orders can be scheduled by the Optimizer.

Capacity planning optimization to meet project deadlines
Planners and schedulers can now use capacity planning optimization to determine when and where
to increase craft capacity to meet project deadlines or maximize turnaround savings within a limited
budget. The optimization identifies the minimum capacity increases needed by craft, shift, and day,
helping you plan your workforce more effectively. You can configure scenarios with project end dates

visualizations. For more information, see Improving capacity planning with what-if scenarios.
Queue worker distribution management for execution service pods
As a system administrator, you can now manage how optimization jobs are distributed across
execution service pods to balance workload and optimize resource usage. Maximo
Optimizer automatically distributes jobs evenly across available pods,
assigning new jobs to the pod with the fewest active jobs. When all pods reach the maximum queue
worker limit, new jobs wait in a pool until capacity becomes available. For more information, see
Managing queue worker distribution across execution service pods.

Large Neighborhood Search algorithm for large-scale optimization
The Large Neighborhood Search (LNS) algorithm handles large-scale dispatching problems with thousands of work orders. You can use it to solve complex scheduling problems that involve thousands of work orders across multiple days and regions. The algorithm supports global optimization, multi-day dispatching with overnight tasks, and improved performance for large problem sets. For more information, see Large neighborhood search algorithm for large-scale optimization.

For example, you can ask to add capacity for a resource, change work order priorities, remove precedence between tasks, or adjust constraints. The optimizer understands your request, applies the changes, and shows you the results. This makes what-if analysis easier and faster. For more information, see Running what-if analysis with natural language.

Removed support for using Oracle stored outlines at session startup

supported for connections to Oracle 7 or 8 databases. If your environment
relies on Maximo Application Suite to enable stored outlines for each database
session, you must now configure Oracle to enable stored
outlines for database sessions outside of Maximo Application Suite. This change

stored outlines, you can configure this usage at the database level in Oracle, such as by using system or session settings or other DBA-managed
mechanisms that are appropriate for your environment. For more information, see ALTER SESSION in the Oracle documentation.
