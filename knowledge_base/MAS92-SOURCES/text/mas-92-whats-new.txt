Installation
Administrative permission modes
You can choose from three administrative permission modes during installation - cluster mode,
namespaced mode, and minimal mode. These modes define the level of administrative capability and
ClusterRole usage available to Maximo Application Suite after installation. When
the operator is installed directly from the Red Hat OpenShift OperatorHub, the operator is installed
without any additional ClusterRoles or nonessential namespace-scoped roles. By default, it operates
in minimal mode. For more information, see Requirements to install in an existing Red Hat OpenShift cluster.
Upgrade
Upgrading user authentication changes 9.1 to 9.2
Starting in Maximo Application Suite 9.2, user and group data for user
authentication is stored in the 
Maximo Manage relational
database, eliminating duplicated user data and the synchronization process between
suite applications. Before you upgrade from Maximo Application Suite 9.1 to 9.2, review the changes to password migration and SCIM
synchronization that helps ensure users can access the system after the upgrade completes. The
upgrade process automatically migrates this required data. For more information, see Upgrading user authentication changes from Maximo Application Suite 9.1 to 9.2
Administrative permission modes
The administrative permission mode cannot be modified during the upgrade process. When you
upgrade from Maximo Application Suite 9.1 to 9.2 by using mas upgrade command in the
CLI, the administrative permission is automatically set to cluster mode because the cluster mode is
used in 9.1 and this configuration is inherited during the upgrade. For more information, see Requirements to install in an existing Red Hat OpenShift cluster
Deprecated user management APIs removed
User and group management APIs that were deprecated in Maximo Application Suite
9.1 are now removed in 9.2. Use the new user management APIs instead. For more information, see
User management APIs in Maximo Application Suite 9.1 and later.

User management
Centralized management of user data
Starting in 9.2, user synchronization is removed for all applications. User
and group data is now stored exclusively in the system relational database, eliminating duplicated
user data and the synchronization process between suite applications. For more information, Centralized user management in Maximo Application Suite 9.2.
Electronic signature for LDAP authentication
You can configure electronic signature validation to use LDAP credentials instead of local
application passwords. Users who authenticate through LDAP can confirm and approve sensitive actions
by using their enterprise credentials. For more information, Enabling electronic signature for LDAP authentication.
Configuration for multiple identity providers 
Starting in Maximo Application Suite 9.2, you can configure multiple identity
providers, such as LDAP, SAML, or OIDC, for the same authentication type in the user interface. This
capability, previously available only through API and command-line interfaces, now provides
administrators with an intuitive, streamlined configuration experience. For more information, see
Configuring multiple identity providers in the user interface.

JSON Web Token expiration
Previously, the JSON Web Token had a short expiry time and required frequent regeneration. You
can now generate the JSON Web Token greater than 90 days or without any expiration time. For
example, you can specify the mas-jwt-expiry-duration header name as
P100Y for a 100-year duration or NEVER to never expire. for more
information, see Configuring Maximo Application Suite to synchronize user and groups with SCIM 2.0

Application configuration
Operator improvements
Support for persistent volume access modes has been extended to include RWX (ReadWriteMany) and
RWO (ReadWriteOnce), providing greater flexibility in storage configuration. Access modes can be
configured in the Application Configuration page in the Admin dashboard. Important: This value is
set during initial creation and cannot be modified later without data loss.For more information,
see Getting started with Application Configuration Maximo Application Suite 9.1 and later.
Upload improvements
When you modify application files, delta files are automatically created and updated during
upload of the application compressed file. A manual save is not required for each file. The publish
action works immediately after uploading the compressed file package. If you decide to modify any
default JavaScript code for a default application, you are warned that this could affect future
application upgrades. You might lose your customizations. For more information on best practices and
avoiding default JavaScript modifications, see Maximo Application Framework configuration practices.
Canvas improvements
Canvas rendering has been improved to better support full-page layouts, making it easier to view
and work with complete pages directly within the Canvas panel. Support for
rendering dialogs has been added, allowing dialogs to be viewed, changed, and customized entirely
within the Canvas panel. The Canvas panel now supports box
and border layout guidelines to help you align and structure content more easily while editing. You
can toggle guidelines on or off using the Guides option, allowing you to show
or hide layout boundaries as needed. For more information, see Application preview.
Faster preview build times
Preview build times are significantly faster due to improved use of shared libraries in the
build process. This reduces startup and rebuild time by 50-80%, allowing you to preview applications
more quickly. For example, a preview that previously took 60 seconds to build and start now
completes in 10-30 seconds. For more information, see Application preview
Configurable logging in preview mode
Logging can be configured in preview mode using the default-log-level
attribute in your app.xml file, making it easier to debug and troubleshoot
during development. You can add the default-log-level attribute to your
<maximo-application> element with values including trace,
debug, info, warn, or error.
Each level controls the verbosity of log output, from most verbose (trace) for deep
debugging to minimal logging (error) for production simulation. For more
information, see Application logging configuration.
Preview and publish progress tracking
Real-time progress indicators help you track the current phase of preview and publish actions.
Enhanced error feedback helps you quickly diagnose issues and take corrective action. Build logs are
accessible from the failure toast notification and from the action menu, providing detailed
diagnostic information. For more information, see Preview and publish progress tracking.
Preview and publish queue
A queue manages preview and publish actions, ensuring structured and predictable execution when
multiple users work simultaneously. Requests are processed in first-in, first-out (FIFO) order. When
multiple users trigger preview or publish actions, requests are placed in a queue and executed
automatically in sequence. You can see your position in the queue and understand when your request
will run. The queue applies to starting a preview server, publishing an application, and save and
preview operations. For more information, see Preview and publish queue.
Delta migration improvements
Delta file generation is more reliable and complete. Delta files are now generated during
publishing for all XML files, ensuring changes are consistently captured and included in migrations.
Custom files added from the src directory and internationalization files from
public/i18n are included as part of migration. Support for
<code-comment> elements has been added to delta files, improving upgrade and
migration scenarios. For more information, see Delta file overview.
Downloadable preview and publish logs
Preview and publish logs are available for download directly from the user interface, making it
easier to review run details and troubleshoot issues. When you start a preview, a log file is
created for your user account and the specific application you are editing. The log file remains
available while you continue editing the application. If you switch to a different application and
return, the logs are reset. To preserve logs, download them before switching applications or closing
the editor. The logs include detailed information for all server-side steps performed during preview
and publish. For more information, see Downloadable preview and publish logs.
Documentation improvements
Product documentation is available from the help menu of the Application Configuration user
interface. Best practices information, REST API documentation, and Training videos are accessible
from the help menu.IBM online documentation has been consolidated for easier navigation.
