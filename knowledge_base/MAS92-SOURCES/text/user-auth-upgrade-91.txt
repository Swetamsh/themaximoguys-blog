Upgrading user authentication changes from Maximo Application Suite 9.1 to 9.2
Upgrading user authentication changes from Maximo Application Suite 9.1 to
9.2
Starting in Maximo® Application Suite 9.2, user and group data for user
authentication is stored in the system relational database, which eliminates duplicated user data
and the synchronization process between suite applications. 
When you upgrade from Maximo Application Suite 9.1 to 9.2, the system
automatically migrates this required data by running a pre upgrade process.
The pre-upgrade process uses a datamodel-migration job to updates
authentication mappings and synchronizes required SCIM fields, including
externalId, so that users can continue to sign in. 
Before you upgrade
 Run
the Integrity Checker utility regularly and before the upgrade to identify and fix database
integrity issues. For more information, see Running Integrity Checker.
To run the Integrity Checker, use the Tools API or run the validate_integ.sh
script directly inside the maxinst pod.
Identify and resolve issues.
Verify that all reported issues are resolved before you proceed with the upgrade. For more
information, see Integrity checker messages.
After you upgrade
After the Maximo Application Suite upgrade, validate that authentication and
identity data successfully migrated.
 Verify that the datamodel-migration job
completed successfully by checking the log for errors. To view the log file, log in to Red Hat® OpenShift® Container Platform and select
Workloads > Pods. Search for
the instance_id-datamodelmigration log file.
 Verify that all user accounts can successfully log in. 
If you encounter any failures during validation, document the error messages, job logs, and
affected user accounts for troubleshooting. For more information, see Validating upgrade from Maximo Application Suite 9.1 to 9.2.
Tip: If you experience temporary migration failures during the upgrade process, see Temporary migration failures during upgrade from 9.1 to 9.2. These failures are
typically transient and resolve automatically as the upgrade progresses.
Optional: Reapply customized email templates
 After the upgrade completes,
manually reapply any customization that you made to system event email templates in 9.1 or earlier.
The upgrade process does not automatically migrate customized email template content.
You can configure any custom email templates in the user
interface.
If 
Maximo Manage is deployed
Use the Communication Template application in 
Maximo Manage to reconfigure email templates. For more information, see Configuring system event emails for Maximo Manage deployments in Maximo Application Suite 9.2.
If 
Maximo Manage is not deployed
Use the Email templates page for suite applications to reconfigure email templates. For more information, see Configuring system event emails for suite application deployments in Maximo Application Suite 9.2.
MongoDB user and group collections
During the upgrade, the MongoDB user and group collections are renamed to
User_pre_upgrade_91_backup and Group_pre_upgrade_91_backup. These
collections remain in available for backup purposes and no longer used, but you can remove them if
you no longer need them. All user and group data is now stored in the system relational database. 
Validating upgrade from Maximo Application Suite 9.1 to 9.2
After you upgrade from Maximo Application Suite 9.1 to 9.2, validate data model migration, user synchronization, Kyverno policies, and read-only file system configurations to verify system stability and compliance.
