Upgrading Maximo Manage checklist
Upgrading 
Maximo Manage checklist
Use this checklist to plan and prepare to upgrade from one version of 
Maximo® Manage to the next version.
Maximo Manage upgrades include the following considerations. 
Version compatibility and upgrade paths
Java™ version changes and customization recompilation
Red Hat® OpenShift® Container Platform cluster requirements
Database backup and integrity validation
Customization and integration testing
Upgrade readiness
 Verify that your current 
Maximo Manage version is supported for direct upgrade to the target
version. 
The upgrade policy supports n-1 versions in a cluster, which means that you can upgrade directly
from the version just before the current one. For example, if your target Maximo Application Suite and 
Maximo Manage version to
upgrade to is 9.1.x, then you can upgrade directly from any 9.0.x version in a cluster. However, you
cannot upgrade directly from any Maximo Application Suite 8.11.x or 
Maximo Manage 8.7.x version. In this case, you need to upgrade first to
9.0.x and then to 9.1.x.
 Review the release notes for the target version and
documentation to understand new features, updates, and deprecated functions. For more information,
see Maximo Application Suite Releases information and What's new in 
Maximo Manage.
 Verify that your Red Hat OpenShift Container Platform
cluster meets the requirements for the target 
Maximo Manage
version. For more information, see Software Product Compatibility Reports (SPCR). 
 Plan your upgrade schedule.
Determine when you can upgrade
Upgrade in a test environment
Troubleshoot your test upgrade
Upgrade your production environment
 Check compatibility for industry solutions and add-ons.
For more information, see Deployment of industry solutions and add-ons.
 If you are upgrading from Maximo Application Suite 9.1 to 9.2, review the upgrade process for user authentication. For
more information, see Upgrading user
authentication.
Database preparation
Disable all custom triggers
 Disable all custom triggers that exist for any table in
your 
Maximo Manage database, for example, stored procedures,
triggers, views, and synonyms. The upgrade process does not re-create or remove these objects.
Reapply custom triggers after your database is upgraded as part of activating 
Maximo Manage.
Commit any database configuration changes
 Commit any pending database configuration changes. Run
the following SQL queries to verify that all changes are committed:
SELECT count(*) from maxobjectcfg where changed != 'N'
SELECT count(*) from maxsysindexes where changed != 'N'If any positive row count
values are returned, apply or discard the configuration changes before proceeding.
Back up Maximo Application Suite instance
 Back up your production Maximo Application Suite instance. For more information, see Backing up and restoring IBM Maximo Application Suite components and applications.
Prepare a test database
 Prepare a test database as a duplicate of the production
database. For more information, see Backing up Maximo Manage databases.
Customization preparation
 Create or update customization archives to store specific
changes, such as Java classes, XML files, and database scripts. For more information,
see Adding customization archives or Creating customization archives.
 If you are upgrading to 
Maximo Manage 9.1, which supports Java 17, recompile
customization archives. For more information, see 
Maximo Manage 9.1 with Java
17.
Test environment
 Maximo Application Suite only supports instances in the same cluster if the
versions are the same with one minor difference. For example, 9.1.x and 9.0.x, but not 9.1.x and
8.11.x. If you are using different versions, carefully review the release notes and catalog content.
Shared components must use versions that are supported by all instances. To avoid conflicts, do not
use different catalogs in the same shared cluster.
 Test the regular and online upgrade in a testing
environment. For more information, see Reducing system downtime.
 Use 
Maximo Manage logs to check and fix any errors. For more information, see
Troubleshooting the upgrade using 
Maximo Manage logs.Tip: Keep your testing environment
with application servers started so that you can measure the actual downtime that it takes
considering the production environment. 
Integrity Checker
 Run
the Integrity Checker utility regularly and before the upgrade to identify and fix database
integrity issues. For more information, see Running Integrity Checker.
To run the Integrity Checker, use the Tools API or run the validate_integ.sh
script directly inside the maxinst pod.
Identify and resolve issues.
Verify that all reported issues are resolved before you proceed with the upgrade. For more
information, see Integrity checker messages.
