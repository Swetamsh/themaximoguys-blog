What's new in Maximo Monitor 9.2

Learn more about what's new and changed in Maximo Monitor 9.2.

Prerequisite software changes

For information about prerequisite software changes, see What's new in IBM® Maximo Application Suite 9.2. New features and enhancements

Architecture enhancements

Stand-alone architecture with optional IoT Platform
Maximo Monitor 9.2 introduces a re-architected IoT integration that removes its dependency on the IoT Platform (IoTP). Maximo Monitor 9.2 operates as a stand-alone application and serves as the single system of record for gateway, device, and API key management, with all authentication and authorization handled centrally within Maximo Monitor. IoTP is optional and deploys only when MQTT-based ingestion is required, providing a reduced, lightweight runtime that retains only essential messaging components. This architecture reduces infrastructure footprint, improves reliability, and supports multiple ingestion methods with a consistent security model. For more information, see Technical overview of Maximo Monitor 9.2.
Centralized gateway and device management
Maximo Monitor 9.2 provides built-in capabilities to create and manage gateways and devices, and to view recent device events, eliminating the strict need for a separate IoT tool. Device, gateway, and authentication data are migrated into the Monitor database during upgrade, eliminating duplicate registries and simplifying lifecycle management. All authentication tokens are managed and stored directly within Monitor, and any ingestion source authenticates directly with the Maximo Monitor data source, ensuring a consistent and unified security model.

Data ingestion enhancements

CSV file ingestion
CSV-based data ingestion provides a flexible alternative to real-time streaming protocols for Asset Performance Management (APM) and Condition-Based Maintenance (CBM). Maximo Monitor supports CSV-based data ingestion as an easily accessible alternative to real-time streaming protocols like MQTT or HTTP. This approach provides organizations with a straightforward method to implement without the complexity of establishing continuous data connections. CSV ingestion bridges this gap by allowing external systems to export time-series data in standardized CSV formats. Maximo Monitor can then periodically ingest this data from accessible storage locations such as IBM Cloud Object Storage, AWS S3 buckets, or Persistent Volumes. For more information, see CSV file ingestion.
Multiple CSV ingestion methods
Maximo Monitor supports multiple methods for ingesting CSV files into its ingestion pipeline, enabling both manual and automated data flows. CSV ingestion can be performed by using the Monitor UI, APIs, or external systems such as Edge Data Collector (EDC). The ingestion behavior depends on the configured storage type: Persistent Volume (PV) or Cloud Object Storage. UI-based uploads are commonly used for smaller datasets, configuration files, and ad hoc or one-time imports. API-based uploads support automated workflows and batch-based data ingestion. External ingestion systems, such as Edge Data Collector (EDC), can write CSV files directly to the Cloud Object Storage bucket, enabling high-volume ingestion by bypassing UI and API upload limits.
Edge Data Collector fallback system
CSV file ingestion is a data collection method that provides robust data buffering and automatic fallback capabilities for edge devices. The Edge Data Collector fallback system helps ensure continuous data collection and zero data loss during network outages or connection failures. The system automatically switches between publishing methods and stores data locally when primary connections are unavailable. The fallback system provides automatic failover, local data persistence, zero data loss after the detection period, and multi-level redundancy. The system supports primary publisher (MQTT or Cloud Object Storage), secondary publisher (Cloud Object Storage or PV), tertiary publisher (PV), and automatic retry to primary every 1 hour. For more information, see Edge Data Collector fallback system.

Security and access control enhancements

Resource-based access control
Resource-based access control (RBAC) determines which data a user can see based on rules that are defined for specific resource types in Maximo Monitor applications. Instead of granting access to all available data, RBAC can ensure that users see only the subset of resources that they are permitted to access. Resource-based access control applies to common Monitor resource types, including assets, locations, systems, organizations, sites, device types, devices, and gateways. These resources are filtered based on the restriction rules that are returned in the user profile. Resource-based access control complements role-based access control, rather than replacing it. Role-based permissions determine what actions that a user can perform, while resource-based access control determines which data the user can see. For more information, see Resource-based access control.

Analytics enhancements

AI-generated alert insights
Maximo Monitor 9.2 introduces AI-generated alert insights that help you detect meaningful patterns and data gaps for assets, locations, and devices. You can configure frequency-based alerts by using AlertByOccurrencesCount and no-data alerts by using NoDataAlert. When configured alerts meet the defined conditions, the system triggers alerts in Monitor and can send them to Maximo Manage so that you can review AI-powered insights in the Tickets application. For more information, see AI-generated alert insights and Configuring alerts for AI-generated insights.
Hierarchy dashboards
Maximo Monitor 9.2 introduces hierarchy dashboards that show aggregated data from child resources on parent resource dashboards. You can use hierarchy dashboards for locations, assets, systems, sites, and organizations to build dashboards that combine data from related resources without creating new KPIs or duplicating data. For more information, see Configuring hierarchy dashboards.
