Installation

Administrative permission modes
You can choose from three administrative permission modes during installation - cluster mode, namespaced mode, and minimal mode. These modes define the level of administrative capability and ClusterRole usage available to Maximo Application Suite after installation.

When the operator is installed directly from the Red Hat OpenShift OperatorHub, the operator is installed without any additional ClusterRoles or nonessential namespace-scoped roles. By default, it operates in minimal mode. For more information, see Requirements to install in an existing Red Hat OpenShift cluster.

Upgrade

Upgrading user authentication changes 9.1 to 9.2
Starting in Maximo Application Suite 9.2, user and group data for user authentication is stored in the Maximo Manage relational database, eliminating duplicated user data and the synchronization process between suite applications. Before you upgrade from Maximo Application Suite 9.1 to 9.2, review the changes to password migration and SCIM synchronization that helps ensure users can access the system after the upgrade completes. The upgrade process automatically migrates this required data. For more information, see Upgrading user authentication changes from Maximo Application Suite 9.1 to 9.2
Administrative permission modes

The administrative permission mode cannot be modified during the upgrade process. When you upgrade from Maximo Application Suite 9.1 to 9.2 by using mas upgrade command in the CLI, the administrative permission is automatically set to cluster mode because the cluster mode is used in 9.1 and this configuration is inherited during the upgrade. For more information, see Requirements to install in an existing Red Hat OpenShift cluster

Deprecated user management APIs removed
User and group management APIs that were deprecated in Maximo Application Suite 9.1 are now removed in 9.2. Use the new user management APIs instead. For more information, see User management APIs in Maximo Application Suite 9.1 and later.

Performance

Cluster Performance Insights dashboard
The Cluster Performance Insights (CPI) dashboard is available in customer-managed environments to provide a centralized interface that is used to collect and help you analyze performance data from your Maximo Application Suite cluster. Use the dashboard to identify performance issues and optimize resource usage.

For more information, see Cluster Performance Insights dashboard.

Authorization services

User settings and purchasing options
To align and centralize user management, you can configure user settings and purchasing options for Maximo Manage users. These options that were originally in Maximo Manage are now available in the Users page. You can specify these options by selecting Suite > Access and usage > Users.
User settings
When Maximo Manage is deployed, you can configure the following options when you create a user.
  • Default site
  • Use default site as a display filter
  • Storeroom site for self service requisitions
  • Default storeroom for self service requisitions
  • Default repair facility
  • Repair facility site
  • Access to inactive sites
Purchasing

When you create users for Maximo Manage in suite security, you can give the user permission to purchase items by adding them to general ledger (GL) accounts. You can create users by selecting Suite > Access and usage > Users from the side navigation menu. For more information, see General ledger accounts.

Security groups
Entitlements for cloned and custom applications
Organizations can extend Maximo Application Suite by creating cloned or custom applications. By assigning entitlement, these applications can operate within the standard security, access, and licensing framework. For more information, see Entitlement for cloned and custom applications in Maximo Application Suite 9.2
Group access to sites
To align and centralize security management of security groups, you can give groups access to records and data in all sites or specify access to individual sites. The Sites tab originally in the Security groups (Manage) application in Maximo Manage is now available in suite security. You can specify access to sites in Security groups by selecting Suite > Access and usage > Security groups.
Group access to object structures
To align and centralize security configuration for users, you can give groups access to object structures. The Object structures tab originally in the Security groups (Manage) application in Maximo Manage is now available in suite security. You can specify access to object structures in Security groups by selecting Suite > Access and usage > Security groups. For more information, see Object structures and security groups in Maximo Application Suite 9.2.

User management

Centralized management of user data

Starting in 9.2, user synchronization is removed for all applications. User and group data is now stored exclusively in the system relational database, eliminating duplicated user data and the synchronization process between suite applications. For more information, Centralized user management in Maximo Application Suite 9.2.

Electronic signature for LDAP authentication
You can configure electronic signature validation to use LDAP credentials instead of local application passwords. Users who authenticate through LDAP can confirm and approve sensitive actions by using their enterprise credentials. For more information, Enabling electronic signature for LDAP authentication.
Configuration for multiple identity providers

Starting in Maximo Application Suite 9.2, you can configure multiple identity providers, such as LDAP, SAML, or OIDC, for the same authentication type in the user interface. This capability, previously available only through API and command-line interfaces, now provides administrators with an intuitive, streamlined configuration experience. For more information, see Configuring multiple identity providers in the user interface.

Configuration

Configuring storage endpoints for Maximo Manage
You can configure storage endpoints by adding parameters to the ManageWorkspace custom resource in the Red Hat OpenShift console. For more information, Configuring storage endpoints
Support for additional languages in Maximo Manage

You can now add languages to Maximo Manage that are not provided with Maximo Application Suite. During deployment and activation, you can provide your own language files in a customization archive to support your organization's language requirements. For more information, see Adding unsupported languages.

JSON Web Token expiration
Previously, the JSON Web Token had a short expiry time and required frequent regeneration. You can now generate the JSON Web Token greater than 90 days or without any expiration time. For example, you can specify the mas-jwt-expiry-duration header name as P100Y for a 100-year duration or NEVER to never expire. for more information, see Configuring Maximo Application Suite to synchronize user and groups with SCIM 2.0
SMTP OAuth2 Authentication for outbound emails

You can configure OAuth2 credentials for the SMTP server for outbound emails in Maximo Application Suite by using SMTP configuration. For more information, see Simple Mail Transfer Protocol configuration.

Configuring system event emails in the user interface
To streamline the management of email notifications for user management operations, you can configure the templates in the user interface for system event emails, such as the welcome email or password reset email that are sent to users. Depending on your deployment, you use different processes.
  • If Maximo Manage is deployed, use the Communications template application. For more information, see Configuring system event emails for Maximo Manage deployments.
  • If Maximo Manage is not deployed and other suite applications are deployed, such as Maximo Monitor, Maximo Real Estate and Facilities, and Maximo Visual Inspection, use the Email templates page. For more information, see Configuring system event emails for suite application deployments.
After you upgrade to 9.2, you must manually reapply any customized email templates.
Adoption metrics
Adoption metrics track how users engage with product features in Maximo Application Suite and Maximo Application Suite as a Service. These metrics can help IBM understand feature usage, user engagement, and product adoption trends to help improve the product experience. For more information, see Adoption metrics.

AI features and AI Service

Adopt the new Maximo Assistant
Instead of navigating multiple dashboards or piecing together context, Maximo Assistant connects it for you, helping you move faster from question to action. The assistant can now act as a single agent that analyzes your requests and works across a defined set of AI tools to answer them. You can ask questions like "What assets need my attention?", "How is asset [number] doing?", and "How do I do [task] in Maximo Manage?"

For more information, see Enabling agentic Maximo Assistant.

Get AI-generated insights into asset condition and alerts
AI-generated insights combine asset condition, maintenance history, and failure data to highlight what needs attention and why. Whether you are reviewing an asset or responding to an alert, you get a view of risk along with recommended actions, all in context.

For more information, see AI-generated asset insights, AI-generated alert insights, or Enabling AI insights for assets and alerts.

Extract data from lease documents
Use AI document extraction to extract data from lease documents and populate fields in lease abstracts in Maximo Real Estate and Facilities. You can configure extraction rules to define which fields AI populates, reducing the time spent manually reviewing documents and entering data.

For more information, see Creating lease abstracts and Enabling AI to create lease abstracts in Maximo Real Estate and Facilities.

Extend AI to new use cases
Create custom AI tools by using Maximo Manage automation scripts, object structures, or workflows, and connect your own tools and agents to the Maximo MCP server.

For more information, see Developing custom integrations and tools for AI Service.

Take advantage of best practices and troubleshooting guides
Maximo Application Suite documentation now includes detailed testing guidance and best practices for AI features, including common findings and guidance on fine-tuning performance.

For more information, see Testing AI features.

Use a redesigned AI configuration experience
The updated AI configuration application streamlines activation and management for AI features. View model status, enable capabilities with one click, and access AppPoint usage dashboards.

For more information about using the AI configuration application, see Adding AI configurations.

Track AI Service AppPoint use
You can now track AppPoint use for AI Service on licensing dashboards. To access the dashboards, from the AI configuration application, click Actions > Check AppPoints and in the Instances table, locate AI Service.

Application configuration

Operator improvements
Support for persistent volume access modes has been extended to include RWX (ReadWriteMany) and RWO (ReadWriteOnce), providing greater flexibility in storage configuration. Access modes can be configured in the Application Configuration page in the Admin dashboard. Important: This value is set during initial creation and cannot be modified later without data loss.

For more information, see Getting started with Application Configuration Maximo Application Suite 9.1 and later.

Upload improvements
When you modify application files, delta files are automatically created and updated during upload of the application compressed file. A manual save is not required for each file. The publish action works immediately after uploading the compressed file package.

If you decide to modify any default JavaScript code for a default application, you are warned that this could affect future application upgrades. You might lose your customizations. For more information on best practices and avoiding default JavaScript modifications, see Maximo Application Framework configuration practices.

Canvas improvements
Canvas rendering has been improved to better support full-page layouts, making it easier to view and work with complete pages directly within the Canvas panel. Support for rendering dialogs has been added, allowing dialogs to be viewed, changed, and customized entirely within the Canvas panel. The Canvas panel now supports box and border layout guidelines to help you align and structure content more easily while editing. You can toggle guidelines on or off using the Guides option, allowing you to show or hide layout boundaries as needed.

For more information, see Application preview.

Faster preview build times
Preview build times are significantly faster due to improved use of shared libraries in the build process. This reduces startup and rebuild time by 50-80%, allowing you to preview applications more quickly. For example, a preview that previously took 60 seconds to build and start now completes in 10-30 seconds.

For more information, see Application preview

Configurable logging in preview mode
Logging can be configured in preview mode using the default-log-level attribute in your app.xml file, making it easier to debug and troubleshoot during development. You can add the default-log-level attribute to your <maximo-application> element with values including trace, debug, info, warn, or error. Each level controls the verbosity of log output, from most verbose (trace) for deep debugging to minimal logging (error) for production simulation.

For more information, see Application logging configuration.

Preview and publish progress tracking
Real-time progress indicators help you track the current phase of preview and publish actions. Enhanced error feedback helps you quickly diagnose issues and take corrective action. Build logs are accessible from the failure toast notification and from the action menu, providing detailed diagnostic information.

For more information, see Preview and publish progress tracking.

Preview and publish queue
A queue manages preview and publish actions, ensuring structured and predictable execution when multiple users work simultaneously. Requests are processed in first-in, first-out (FIFO) order. When multiple users trigger preview or publish actions, requests are placed in a queue and executed automatically in sequence. You can see your position in the queue and understand when your request will run. The queue applies to starting a preview server, publishing an application, and save and preview operations.

For more information, see Preview and publish queue.

Delta migration improvements
Delta file generation is more reliable and complete. Delta files are now generated during publishing for all XML files, ensuring changes are consistently captured and included in migrations. Custom files added from the src directory and internationalization files from public/i18n are included as part of migration. Support for <code-comment> elements has been added to delta files, improving upgrade and migration scenarios.

For more information, see Delta file overview.

Downloadable preview and publish logs
Preview and publish logs are available for download directly from the user interface, making it easier to review run details and troubleshoot issues. When you start a preview, a log file is created for your user account and the specific application you are editing. The log file remains available while you continue editing the application. If you switch to a different application and return, the logs are reset. To preserve logs, download them before switching applications or closing the editor. The logs include detailed information for all server-side steps performed during preview and publish.

For more information, see Downloadable preview and publish logs.

Documentation improvements
Product documentation is available from the help menu of the Application Configuration user interface. Best practices information, REST API documentation, and Training videos are accessible from the help menu.

IBM online documentation has been consolidated for easier navigation.

IBM Maximo Renewables

Maximo Renewables empowers renewable energy operators to maximize asset performance, minimize downtime, and optimize energy generation. This renewables asset performance management software uses advanced analytics, AI-driven insights and automated workflows, identifying root causes and recommending corrective actions in near real-time. Designed for wind, solar, and battery storage systems, Maximo Renewables helps bridge the gap between expected and actual energy output, driving greater reliability and profitability.

Maximo Renewables integrates with Maximo Manage. After you deploy Maximo Manage, you can enable Maximo Renewables by contacting the Maximo Renewables team. For more information, see Renewables asset performance management.
