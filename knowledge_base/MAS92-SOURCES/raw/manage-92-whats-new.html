Administration enhancements

Time zone enhancements
The framework that determines the appropriate time zone for date/time-related operations such as scheduling PMs and generating work orders has been enhanced to include new considerations. The following processing rules have been added.
Time zone processing rule Description
PM Determines time zone based solely on PM.
Organization Determines time zone based on Organization.
Site Determines time zone based on Site.
Site, Organization Considers Site time zone first, then Organization.
PM, Asset, Locations, Site, Organization Considers PM first, then Asset, then Location, then Site, then Organization.
PM, Site, Organization Considers PM first, then Site, then Organization.
For more information, see Time Zone Rules.

Automated calibration accuracy validation for standards and assets
Maximo Manage now automatically validates that calibration standards have adequate accuracy specifications when you select a rotating asset as a calibration standard on a work order. This feature ensures compliance with regulatory standards such as ISO/IEC 17025 and ISO 15189 by comparing the accuracy specifications of the standard against the asset under calibration. The validation includes unit conversion when necessary and provides configurable warning or enforcement modes. For more information, see Validating calibration accuracy between standards and assets.
You can now bypass the accuracy check for specific assets in special cases. Select the Bypass Accuracy Validation checkbox on either the asset being calibrated or the rotating asset standard. Maximo Manage then skips the check and lets you continue. Use this option for older equipment, emergency situations, or non-standard equipment.

Additional fields for predecessor information
In the Graphical Scheduling or Graphical Scheduling - Large Projects application, create a project and create a work query to specify the work orders. Create an optimization scenario. Three new fields are available when you edit a constraint. The same fields are available in the Work Order Tracking application, when you edit or display a relationship constraint.
  • Maximum Lead Lag Hours: It sets the maximum allowed delay between a predecessor task and its successor. For example, if Task A happens before Task B, this value defines how many hours at the most Task B can start after the start or end of Task A.
    Note: The default value of 0 is not considered.
  • Optional Relationship: It indicates whether the dependency between a task and its predecessor must always be followed. If set to yes, the dependency is mandatory and the system treats it as a hard rule. If set to no, the dependency is optional and the system treats it as a soft rule that is ignored, if the relaxOptionalRelationship model parameter is set to true.
  • Use Lead Lag As Shift Hours: It specifies how the lead-lag duration is interpreted. When set to no, the lead-lag is counted in calendar hours, that is, continuous time. When set to yes, the lead-lag is counted in shift hours, that is, working hours. For example, if a shift ends at 6 PM, Task A ends at 5 PM, and lead-lag is set to 2 hours, then if set to no, that is, calendar hours, Task B can start at 7 PM on the same day. If set to yes, that is, working hours, Task B would start on the next working day at 9 AM, after two working hours have passed from the 5 PM end time of Task A.

Explain why a work order is not assigned in Optimizer
In previous versions of Optimizer when work orders could not be scheduled, the reason could be given as This work can not be assigned by the optimizer with all selected optimization constraints. which was not a helpful message and did not tell you why the work could be scheduled. Starting in Maximo Manage 9.2, a better error messaging is provided to indicate exactly why the work could not be scheduled. It is implemented for the Graphical Assignment and Graphical Scheduling models.
In Graphical Assignment, a new AnalyzeUnperformed parameter is introduced. When AnalyzeUnperformed is set to true there is a post process where every single work order that was not scheduled is analyzed and a helpful alert is displayed stating which business constraints could not be satisfied or which other work orders were in conflict that could not prevent the work from being scheduled.
In Graphical Scheduling, there is a new iterativeConflictFixVerbose parameter which when set to False prints all the constraints violated by the work orders that could not be scheduled.
These two parameters work across both models to give better and more comprehensive explanations as to why certain work orders could not be scheduled allowing you to understand and fix the issues in the schedule and ensure that maximum work orders can be scheduled by the Optimizer.

As a system administrator, you can now manage how optimization jobs are distributed across execution service pods to balance workload and optimize resource usage. When all pods reach the maximum queue worker limit, new jobs wait in a pool until capacity becomes available. Large Neighborhood Search algorithm for large-scale optimization
The Large Neighborhood Search (LNS) algorithm handles large-scale dispatching problems with thousands of work orders. You can use it to solve complex scheduling problems that involve thousands of work orders across multiple days and regions. The algorithm supports global optimization, multi-day dispatching with overnight tasks, and improved performance for large problem sets. For more information, see Large neighborhood search algorithm for large-scale optimization.

For more information, see Running what-if analysis with natural language.

Removed support for using Oracle stored outlines at session startup
Previously, the use of alter session set use_stored_outlines = true was supported for connections to Oracle 7 or 8 databases. If your environment relies on Maximo Application Suite to enable stored outlines for each database session, you must now configure Oracle to enable stored outlines for database sessions outside of Maximo Application Suite. This change aligns with the deprecated status of Oracle stored outlines. If you use stored outlines, you can configure this usage at the database level in Oracle, such as by using system or session settings or other DBA-managed mechanisms that are appropriate for your environment. For more information, see ALTER SESSION in the Oracle documentation.
